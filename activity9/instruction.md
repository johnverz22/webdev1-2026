# Build Portfolio Page — From Scratch

**A step-by-step HTML + CSS activity — Flexbox & Grid**

## How this works

You're building this entire page from an empty folder. There is **no code anywhere in this document** — every step is a description of what to build and where, in plain English. You write the actual HTML and CSS yourself. Your instructor has given you a screenshot of the finished page — that screenshot is your source of truth for spacing, colors, and proportions. Refresh your browser after every change and compare what you see against it.

This only works if you do the steps in order and actually try each one before moving on. If you get stuck on a specific property name, that's fine — ask your instructor, check your notes, or look it up in MDN docs. What you should not do is ask an AI tool to write the rule for you; if you do, you'll have a file that matches the screenshot but you won't be able to answer the checkpoint questions, which are part of your grade and can't be generated by just looking at a finished page.

## Step 2 — The navbar: lay it out side by side

Compare your current plain-stacked result to the screenshot. You need to solve two separate stacking problems here, not one — they're nested inside each other.

**Problem A:** The header's two direct children (the logo text and the `nav` element) need to go from stacked-vertically to sitting in a single row, with one pushed to the far left and the other to the far right, and both vertically centered against each other so neither looks higher or lower than the other.

Think about which CSS property turns an element's direct children into a flexible row/column layout in the first place — that's the property you'll need to set on the header, before anything else about alignment will even apply. Then think about which property controls how children space themselves out along the main row (the one that gives you "first item at one end, last item at the other end, automatic space between them"), and which property controls their alignment along the cross-axis (the one that handles "both centered vertically against each other").

Apply padding around the inside of the header so the content doesn't touch the edges of the browser — look at the screenshot to estimate how much breathing room there is around the logo and links relative to the window edge; a comfortable amount for a navbar like this is usually somewhere in the 25–30 pixel range vertically and 50–60 pixels horizontally. Also add a thin 1-pixel solid bottom border in a light gray to create the dividing line under the navbar, matching the screenshot.

**Problem B:** Even after fixing the header's own row layout, the three list items inside `navbar__links` are still a completely separate stacking problem — they're nested two levels deeper, and fixing the header's layout does not reach down into them. You need to apply the same "turn children into a row" property again, this time targeting the link list itself, plus a property that adds consistent horizontal spacing between the three links without you having to add margin to each one individually. Looking at the screenshot, that spacing looks like roughly 40 pixels between each link.

## Step 4 — The hero section: lay it out as two columns

You need to solve three layout problems here, working from the outside in.

**Problem A — the two main columns.** `.hero`'s two direct children (`hero__text` and `hero__panel`) need to sit side by side instead of stacked. Apply the same "children become a row" property you used on the navbar. Add a property that creates consistent horizontal space between the two columns — looking at the screenshot, that gap looks considerably larger than the 40px you used between nav links, more like 60–65 pixels, since these are two large content blocks rather than three small links. Also set the cross-axis alignment so both columns align to the top of the row, rather than stretching to match each other's height — look closely at the screenshot and notice the right-hand card stack doesn't extend to be exactly as tall as the left column's text block, which tells you the default "stretch" behavior has been turned off in favor of top-alignment.

Add generous padding around the whole section (estimate from the screenshot — this section has noticeably more vertical breathing room than the navbar, closer to 100px top and bottom) and constrain its maximum width so the content doesn't stretch edge-to-edge on a very wide monitor — a max width somewhere around 1140px is typical for a content section like this, centered horizontally on the page.

**Problem B — uneven column widths.** Measure the two columns in the screenshot by eye: the text column on the left appears to take up slightly more horizontal space than the card panel on the right — not double, just modestly more, maybe in a ratio like 6-to-5. There's a flexbox property that lets a flex item claim space proportionally relative to its siblings, independent of how much content it contains. Apply that property to both `hero__text` and `hero__panel`, using values whose ratio roughly matches what you see in the screenshot (for example, one common way to express a "slightly more" relationship is to give one side a value of 1.2 and the other a value of 1).

**Problem C — the card stack inside the panel.** The three `info-card` divs inside `hero__panel` are currently stacking vertically by default (since divs are block-level elements), but they're touching each other with no gap. Even though they're already stacking in the right direction without any flex property at all, you still want to convert `hero__panel` into an explicit flex container, with its direction explicitly set to vertical/column (rather than the default horizontal row), purely so that you're allowed to use a gap property to add even spacing between the three cards — somewhere around 16px looks right against the screenshot. Without making it a flex container, there's no clean way to add that consistent spacing without margin hacks on individual cards.

For the visual styling of the cards themselves (border color, background, padding, text sizes, the accent card's background color), look at the screenshot and estimate values that match — a light warm gray border, white background for the two plain cards, and a warm terracotta/rust background with white text for the accent card is what you're aiming for. Exact hex codes aren't something you can derive from a screenshot precisely, so get reasonably close and ask your instructor if exact brand colors matter for grading.

## Step 6 — The skills section: lay it out with Grid

This is the first section where Flexbox isn't the right tool. Flexbox is built for laying things out along a single row or single column. Here, you want true rows-and-columns behavior, where specific items can span multiple columns — that's what CSS Grid is built for.

Count how the four cards arrange themselves in the screenshot to figure out how many equal-width columns the grid should have at the widest screen size.

### ✋ Predict, then build

Before writing anything, write a one-sentence guess: what do you think the CSS property is called that turns a container into a grid (similar to how `display` had a flex value before), and what property defines how many column tracks that grid has?

Apply `display` with the grid value to `.skills__grid`. Then define the column tracks: you want however many equal-width columns you counted, using a fraction unit so they split the available space evenly rather than being fixed pixel widths. Add a small 1-pixel gap between cards — small enough that it reads as a thin dividing line rather than visible whitespace, with a light gray background color showing through that gap (this is a visual trick: the gap color comes from the *container's* background, not the cards', so give `.skills__grid` a light gray background and give each `.skill-card` itself a white background, and the gap will read as thin gray lines between white cards). A thin 1px border around the whole grid in the same gray ties it together.

Refresh and compare. Your four cards should now sit 3-per-row at the widest width (with the 4th wrapping to a new row) — but all still the same width, since you haven't applied the "wide" treatment yet.

### ✋ Predict, then build

Write a guess for what you think this property might be called, based on the pattern of other multi-word CSS properties you've learned (hint: it starts the same way as the property that defines the columns themselves).

## Step 7 — The contact section: build it (no new layout properties)

Look at the dark section near the bottom of the screenshot: centered text on a dark background — a small label, a heading, a description, and a light-colored button — all centered as a block.

Add a `section` (class like `contact`, `id="contact"`) after the skills section, containing: a small label paragraph, a heading, a description paragraph, and a `mailto:` link styled as a button.

This section does not need flex or grid at all. Every child here is naturally stacking vertically already (they're just paragraphs and a link), and "centered" in this case refers to the *text itself* being centered within its container — that's a simple text-alignment property, not a layout property, applied directly to the section. Set the section's background to a near-black dark color, its text color to white, and its text alignment to centered. Add generous padding matching the visual rhythm of the hero section (around 100px top/bottom looks consistent with the rest of the page).

The label and heading should likely need their own lighter-tinted color variants for readability against the dark background (look at the screenshot — the label appears in a soft peach/light-orange tone, and the description text in a light gray, both lighter than the white heading) — consider adding modifier classes for this if you haven't already created reusable type classes for labels and headings in earlier sections.
