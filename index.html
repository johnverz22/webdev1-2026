01

display: flex

container

Turns an element into a flex container. Its direct children automatically become flex items and line up in a row by default — no floats, no inline-block hacks.

display
1
2
3
.container { display: flex; }
i

Note: Switch back to block and the boxes stack vertically like normal divs. The moment you add display: flex, the children snap into a horizontal row — that's the flex layout algorithm taking over.

02

flex-direction

container

Sets the main axis — the direction items are laid out. Everything else (justify-content, align-items) is defined relative to whatever direction you pick here.

flex-direction
1
2
3
.container { display: flex; flex-direction: row; }
i

Note: row flows left→right, column flows top→bottom. The -reverse variants flip the start/end points — item 1 jumps to the opposite end. This is the single most important property: it decides what "main axis" even means for the rest of the demos.

03

flex-wrap

container

By default, flex items try to squeeze onto one line, shrinking if needed. flex-wrap lets them drop onto new lines instead of being crushed.

flex-wrap
1
2
3
4
5
6
.container { display: flex; flex-wrap: nowrap; }
i

Note: With nowrap, six 110px boxes get squeezed to fit the container — they shrink rather than overflow. Switch to wrap and watch them keep their width and flow onto a second line instead.

!

Common mistake: students expect items to overflow the box when they don't fit. They don't — by default flex items shrink (see flex-shrink below). You need flex-wrap: wrap if you want a responsive grid-like flow.

04

flex-flow

container

Shorthand that combines flex-direction and flex-wrap into a single declaration. Purely a convenience — no new behavior.

flex-flow
1
2
3
4
5
.container { display: flex; flex-flow: row nowrap; /* = flex-direction: row; flex-wrap: nowrap; */ }
i

Note: flex-flow: column wrap is exactly the same as writing flex-direction: column; flex-wrap: wrap; on two lines. Use whichever reads clearer in your codebase — both are equally valid CSS.

05

justify-content

container

Distributes items along the main axis — the spacing/positioning between and around items in the direction set by flex-direction.

justify-content
1
2
3
.container { display: flex; justify-content: flex-start; }
i

Note: space-between pushes the first and last item to the edges with equal gaps in between. space-around gives every item equal space on both sides (so edge gaps look smaller than center gaps). space-evenly truly equalizes all gaps, including the edges.

06

align-items

container

Positions items along the cross axis (perpendicular to the main axis) — for a single line of items. Think of it as vertical alignment when in row direction.

align-items
1
2
3
.container { display: flex; align-items: stretch; }
i

Note: stretch is the default — items with no fixed height grow to fill the container's cross-axis size. That's why boxes with explicit heights set here only "reveal" their true height once you switch to flex-start, center, or flex-end.

!

Common mistake: confusing align-items (container property, affects all items at once) with align-self (item property, affects one item). They take the same values but live on different elements.

07

align-content

container

Like justify-content, but for the cross axis — and only matters when there are multiple lines (i.e. flex-wrap: wrap is on and there's leftover space).

align-content (wrap is on)
1
2
3
4
.container { display: flex; flex-wrap: wrap; align-content: flex-start; }
i

Note: Each row here wraps two 130px items. align-content controls how those rows as a group are positioned in the leftover vertical space. If there's only one line, or no wrapping, this property has no visible effect — that's the #1 reason students think it's "broken."

08

gap (row-gap / column-gap)

container

Adds consistent spacing between flex items — without the margin-collapsing headaches of using margins on items. Works on both axes.

gap
1
2
3
4
.container { display: flex; gap: 0px; }
i

Note: gap only creates space between items, never on the outer edges of the container — unlike margins, which would add space around the whole group too. This makes it the cleanest way to space out a row or grid of items.

09

order

item

Changes the visual order of an item without touching the HTML source order. Default value is 0 for every item; lower numbers go first.

order of item "2" (highlighted)
1order:0
2order:0
3order:0
.item-2 { order: 0; /* default */ }
i

Note: Setting item 2's order to -1 moves it before items with order 0; setting it to 5 pushes it after them. This is purely visual — screen readers and Tab key navigation still follow the original HTML order, so use this for cosmetic reordering only, not to fix bad document structure.

10

flex-grow

item

Defines how much an item should expand to fill leftover space in the container, relative to other items' grow values. Default is 0 (don't grow).

flex-grow of item "2" (highlighted) — others stay at 0
1
2grow:0
3
.item-2 { flex-grow: 0; /* default — won't grow */ }
i

Note: With grow:1, item 2 absorbs all the leftover space in the row because it's the only item set to grow. At grow:3 it eats space three times faster than grow:1 would — but with siblings still at 0, the visible result looks the same as grow:1 here. Try giving two items grow values like 1 and 2 to see proportional sharing.

11

flex-shrink

item

Defines how much an item should shrink when the container is too small to fit everyone at their natural size. Default is 1 (items shrink evenly).

flex-shrink of item "2" (highlighted) — container is too narrow for all 3
1
2shrink:1
3
.item-2 { flex-basis: 150px; flex-shrink: 1; /* default */ }
i

Note: Three 150px items can't fit in a 280px box, so by default all three shrink proportionally. Set item 2's shrink to 0 and it refuses to shrink at all — items 1 and 3 absorb the squeeze instead, and item 2 may even cause overflow. Set it to 5 and item 2 shrinks much more aggressively than its siblings.

12

flex-basis

item

Sets the item's starting size along the main axis before flex-grow/flex-shrink are applied. Think of it as a "preferred" width (in a row) or height (in a column).

flex-basis of item "2" (highlighted)
1
2basis:80px
3
.item-2 { flex-basis: 80px; }
i

Note: flex-basis behaves like width in a row layout, but it's the size flexbox uses as the "before adjustments" starting point. With grow and shrink both at 0 here, item 2 stays locked to whatever basis you pick — no negotiation with leftover space.

13

flex (shorthand)

item

Combines flex-grow, flex-shrink, and flex-basis into one declaration: flex: grow shrink basis;. This is the property you'll actually write most often in real projects.

flex shorthand on item "2" (highlighted)
1
20 1 auto
3
.item-2 { flex: 0 1 auto; /* grow shrink basis */ }
i

Note: flex: 1 is the famous "equal share" trick — it expands to 1 1 0%, meaning the item ignores its content size and grows to fill space equally with siblings that also have flex: 1. That's different from flex: auto, which still grows but starts from the item's natural content size.

!

Common mistake: writing flex-grow: 1 alone and expecting it to behave like flex: 1. They're close but not identical — the shorthand also resets flex-basis to 0%, which changes how grow space is calculated.

14

align-self

item

Overrides the container's align-items value for one specific item on the cross axis. Same accepted values as align-items, just scoped to a single child.

align-self of item "2" (highlighted) — container align-items: flex-start
1
2
3
.container { align-items: flex-start; } .item-2 { align-self: center; }
i

Note: Items 1 and 3 obey the container's align-items: flex-start, but item 2 breaks formation because its own align-self wins. This is the one-off escape hatch for "make every item align the same way, except this one."
